# 实战案例：一份官网说明书 → 完整 WDesigner 工程

> 输入是一份从厂商官网随手下载的建库试剂盒说明书 PDF（13 页，v7.0）——没有任何定制
> 信息，所以整个过程可以完整公开。从一句话触发到交付包落盘，一次会话完成（净工作
> 时长约 57 分钟）；人工做的事只有两类：回答 8 组选择题，在几个化学分歧点上拍板。
> 这篇按复刻的视角写：每一步做了什么、你会看到什么、需要你决定什么。

## 开始之前：模型与 Agent 怎么选

**模型务必选多模态的（能读图），并且尽量选长上下文（百万级 token）的档位。**
原因有二：说明书里的流程图、加样表、表格脚注是纯文本抽取必丢的部分，必须靠视觉
通道读；后面液量账本的逐条明细也吃上下文长度。国内可选的多模态模型例如：

- **GLM-5.3-Flash**（多模态、百万级上下文——本案例即用它全程跑完）
- **DeepSeek** 的多模态模型
- **Qwen** 的多模态模型
- **Kimi** 的多模态模型

Agent 用支持 skill / 自定义命令扩展的编码 Agent 即可，例如 **Claude Code、Codex、
WorkBuddy** 等。本案例在 Claude Code 中以 `/mgisp960-devkit` 触发。

## 输入与产出

| | |
|---|---|
| **输入** | 官网下载的 DNA 建库试剂盒说明书 PDF（End Prep → 接头连接 → 磁珠纯化 → PCR 富集 → 文库，96 反应规格） |
| **产出** | `NEBNextUltraIIDNA_V1.0.zip`：分选 / 免分选双 `.wfp` 工程、PCR 温控 XML（16 方法簇）、自动化说明书（HTML + A4 PDF）、Check point 验收文档 |

下面按时间顺序走一遍全过程。

---

## 第 0 步 · 一句话触发

会话里只敲了一行指令，把说明书的位置和期望的产出形态说清楚：

```
/mgisp960-devkit 好的，这个项目里面有一个 NEB 的建库试剂盒说明书，是我从官网上
直接下载的。你看是否能通过这个说明书，直接给我生成一个 WFP 的 W Designer 项目文件？
```

![触发：一句话开工，skill 进入思考](../assets/case-neb-ultra2-dna/01-trigger.png)

注意底部那行 "Grooving… (2m 26s · almost done thinking)"——skill 此刻并没有开始写
代码。按它的门禁纪律，动手前必须先过 S0 需求确认：8 组问题，一组一发，全部拍板
之前不写任何文件。**复刻时你也会遇到同样的节奏：先答题，后开工。**

## 第 1 步 · 先定位材料、先讲边界（S0 前 2 组）

两分多钟后，skill 给出的第一段回复做了三件事。

**第一，定位材料**：它先列了目录，从文件名 `manualE7103-E7645.pdf` 认出这是两个
货号同册的说明书（约 1.3 MB），但按门禁纪律**没有立刻通读**——读说明书理解化学是
下一步 S1 的事，现在只确认材料存在。

**第二，正面回答"能不能做"**：能，产出是 WDesigner 可直接打开的 `.wfp`。但坦率
讲了两点边界：这不是"一键直出"（离心、涡旋这类手工步骤无法直译，需要人在关键点
拍板）；生成后必须实机验证（本地能做到编译通过 + 结构对齐 + 液量账本复核，软件
模拟和上机要在现场完成）。

**第三，发第 1/8 组问题**（PCR 温控 XML 是否随包交付）。用户选了 A（.wfp + XML），
紧跟着第 2/8 组问命名——这一项 skill 被禁止自拟带厂商字样的名字，必须用户拍板，
三个选项各带利弊，用户选了 B（按试剂盒名）：

![材料定位、能力边界与命名选项](../assets/case-neb-ultra2-dna/02-s0-scope-naming.png)

## 第 2 步 · 化学决策：四道真正的选择题（S0 第 4 组）

发问之前，skill 先查了经验库里"须用户选"的分档条目，确保选项和依据是准的。
这一组是分歧最大的地方，四道题每一道都直接改变最终参数：

1. **磁吸后吸取的 Z 策略**——决定回收率与带珠风险。选项 A 极低正 Z + 降速
   （★推荐，免标定、已验证）、B 磁吸位 Z=0（磁珠贴侧壁后底部中央无珠，吸得最净）、
   C 负 Z 刮底（官方允许，但要水跑标定防撞底）；
2. **乙醇补偿吸**——两轮乙醇洗之间要不要显式补吸残留乙醇（残留乙醇抑制下游酶反应）；
3. **枪头复用**——省耗材与防交叉的取舍；
4. **回收取向**——纯度优先还是产量优先。

![化学决策四问，选项带推荐和出处](../assets/case-neb-ultra2-dna/03-s0-chemistry.png)

用户的选择偏激进：Z 策略选了 B（磁吸位 Z=0，吸得最净），同时确认做补偿吸、
枪头按规律复用、纯度优先。这些选择后来全部写进了生成的参数里。

## 第 3 步 · S0 收口：八组拍板汇总

中间的台面耗材（96 整板、换台最多 1 次）、交互文档（要不要说明书、要不要母版）、
验证验收（水跑几轮、验收口径）、环境基线（设备配置号、软件版本串、板位实况）四组
从略——重点是第 8/8 组答完后的汇总表。这张表就是整个项目的"合同"：

![S0 需求确认单：八组拍板结果](../assets/case-neb-ultra2-dna/04-s0-summary.png)

值得看两处：一是表格末尾的**存疑清单**——项目名具体字样、PCR 档位范围这类"现在答
不了"的项被标成非阻塞，到对应环节再补答，而不是卡住流程；二是最后的流程预告
（S1 读说明书 → S2 台面 → S3 账本 → S4 生成 → S5 自检 → S6 交付）。

用户回了一个字："开始"：

![确认完成，流水线启动](../assets/case-neb-ultra2-dna/05-s0-confirmed.png)

## 第 4 步 · 读懂说明书：三张表（S1）

skill 通读了 13 页全文，按双通道纪律抽取：**一切数字走文本层**（体积、温度、时间、
循环数，零转写误差），**流程图和表格结构走视觉层**。这就是开头强调多模态模型的原因。

读完后产出化学理解表。下图能看到流程骨架被压成一行链路（每步带体积和温控参数，
例如 End Prep 是 3+7 µL、20 ℃ 30 min → 65 ℃ 30 min），以及第一张表——试剂分类表，
最右一列直接算出 96 样本的试剂总量（End Prep 酶 288 µL、连接 Mix 2 880 µL……），
这张表后面就是装载定义的雏形：

![S1 化学理解表：流程骨架与试剂分类](../assets/case-neb-ultra2-dna/06-s1-understanding.png)

更重要的是存疑清单里抓出的几个分支：>50 ng / ≤50 ng 对应**两条不同的纯化路线**
（分选要两次加珠两次磁吸，免分选一步 0.9×）；接头稀释谁来做；磁架口径对板型的
连锁约束。每条都让用户拍了板，最后定了：双路径弹窗切换、接头用户手配、
**反应在 PCR 板、纯化转深孔板**（现场磁架是深孔口径，反应板不能直接上磁架——
这个硬件事实把整个台面设计改了向）。

## 第 5 步 · 台面与液量账本（S2/S3）

这一段没有截图，但它决定交付质量。

台面设计先撞上现场硬件：磁架是深孔板口径，反应板不能直接上磁架。解法是反应/混匀
留在 PCR 板（微量精度好），加珠混匀后整板转入深孔板做磁吸——每次转板的残留损失
都定量核算进交付文档。

然后是液量账本：把全部液体操作逐条模拟，逐孔累计体积和液面，跑五项审计（排空
贴液面、吸液没入深度、混匀双约束、体系终态对账、试剂装载五问）。两条路径合计约
950 条活动记录，修正一轮后审计全绿，文库终态 30 µL/孔 精确到位。**复刻时你不需要
懂这层 mechanics——账本不绿 skill 自己会迭代，你只在它需要化学判断时被问到。**

## 第 6 步 · 生成与交付（S4/S6）

`wfp_builder` 直接生成活动树（全活动中文语义命名），配 PCR 方法簇 XML（16 个方法：
预热、End Prep、连接、循环数 3–15 全覆盖的 PCR 簇），说明书沿用上一个已验证项目
的母版版式——版式复用、内容全换。最终的会话总结长这样：

![交付汇总：文件清单、质量关卡、现场三步](../assets/case-neb-ultra2-dna/07-delivery.png)

图里三块值得读：**文件表**（双路径 wfp、16 方法簇 XML、说明书、Check point）；
**质量关卡**（账本五项审计全绿：3B 461 条 / 3A 513 条液体活动，终态文库 30 µL/孔
精确；结构对齐；XML 校验；弹窗与换台后台面互证）；**"现场三步"**——WDesigner 打开
确认 → 软件模拟 → 水跑两轮（首轮按 Check point 的 7 项观察清单摸参数，次轮按
说明书预期验收）。

## 第 7 步 · 现场打开：WDesigner 里见真章

交付包当晚就被拷到现场的 Windows 机器上，用 WDesigner 打开了 `_3A.wfp`——这一步
等于 Check point 里"第 0 步：打开确认"正式通过：生成的文件在实机软件里真实打开，
台面和流程渲染无红。

先看**主台面**。24 个板位全部按定义渲染，最值得看的是每个板位上的备注——它们不是
装饰，是给现场操作员的摆台指令：POS5 八头盒写着"分装连打12列跨全程·换台保留勿动"，
POS11 反应板写着"DNA 50μL/孔 常驻"，POS21 试剂板逐列标了装量（Buffer 100/列3
接头 40/列4-6 LigM…），POS23 废液板标了"空板·单路累计约1112μL/孔"。磁架 POS15/19
空置、振荡位 POS20 留白（洗脱混匀专用），含珠的板不停磁架位——台面纪律全部落在
备注里。页签上还能看到 DESK 2：换台后的第二张台面定义也随文件一起交付：

![WDesigner 打开 · 主台面 24 位与摆台备注](../assets/case-neb-ultra2-dna/08-wdesigner-deck.png)

再切到 **Workflow 画布**。流程从"开始 → Initialize"往下，每个化学阶段一个 Block，
块名直接用中文语义命名——"开机准备·设温"（进度上报"开机 1/9" + 温控模块 6 ℃）、
"并行:PCR预热+待机"（PCR START 预热和待机两个分支同时跑）。现场工程师不查文档
也能读懂流程在干什么；图里还能看到左侧的活动面板（Block/Loop/移液器/机械臂/
温度循环仪），整个工程就是用这些积木搭出来的：

![WDesigner 打开 · Workflow 画布，语义命名与并行分支](../assets/case-neb-ultra2-dna/09-wdesigner-workflow.png)

到这里，"一份说明书 → 一个能打开能读懂的工程"已经闭环。剩下的软件模拟和水跑
两轮（摸参数、定版）按 Check point 清单继续，数据回来后回填参数即可定稿。

## 复刻清单

1. **准备**：说明书 PDF（官网公开的即可）+ 现场硬件三件事（设备配置号、磁架口径、
   软件版本号）——S0 都会问到；
2. **模型**：多模态 + 长上下文（GLM-5.3-Flash / DeepSeek / Qwen / Kimi 的多模态档）；
3. **Agent**：Claude Code、Codex、WorkBuddy 等支持 skill 扩展的编码 Agent；
4. **触发**：`/mgisp960-devkit 这个目录里有一份建库试剂盒说明书，帮我生成 WDesigner 工程`；
5. **配合**：回答 8 组确认题（都有推荐项，可直接"按推荐"），在化学分歧点和无法直译
   的手工步骤上拍板；
6. **收尾**：拿到交付包后按 Check point 清单走现场验证——WDesigner 打开确认 →
   软件模拟 → 水跑两轮（摸参数、定版）。
