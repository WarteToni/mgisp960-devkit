# 实战案例：一份官网说明书 → 完整 WDesigner 工程

> 输入是一份从厂商官网随手下载的建库试剂盒说明书 PDF（13 页，v7.0）——没有任何定制
> 信息，所以整个过程可以完整公开。从 `/mgisp960-devkit` 一句话触发到交付包落盘，
> 一次会话内完成；人工只做了 8 组选择题和几处关键拍板，其余由 skill 流水线跑完。

## 第一步：读懂说明书（S1 化学理解表）

读说明书走"双通道"：**数字走文本层抽取**（体积、温度、时间、循环数——零转写误差），
**流程图和表格结构走视觉读**。

> **模型选择提示**：这一步强烈建议使用多模态模型（能读图的模型）。说明书里的
> 流程图、加样表、脚注小字是文本抽取必丢的部分，纯文本模型会漏掉分支和隐藏约束。

理解表产出三张表：试剂分类（角色 × 储存 × 96 样本总量）、操作序列（五元组：
输入板 + 试剂体积 + 操作 + 温控 + 输出去向）、存疑清单。存疑清单里模型抓出了几个
容易漏掉的分支：>50 ng / ≤50 ng 两条纯化路径、接头稀释的分工、磁架口径对板型的
连锁约束——每条都要用户拍板，不猜：

![S1 化学理解表](../assets/case-neb-ultra2-dna/06-s1-understanding.png)

## 第二步：台面与液量账本（S2/S3——这个 skill 的核心质检）

台面设计先撞上现场硬件：磁架是深孔板口径，反应板不能直接上磁架。解法是反应/混匀
留在 PCR 板（微量精度好），加珠混匀后整板转入深孔板做磁吸——每次转板的残留损失
都定量核算进交付文档。

然后是液量账本：把全部液体操作逐条模拟，逐孔累计体积和液面，跑五项审计（排空贴
液面、吸液没入深度、混匀双约束、体系终态对账、试剂装载五问）。两条路径合计约
950 条活动记录，最终审计全绿、文库终态 30 µL/孔 精确。

这次实测账本抓出一个单看工程文件完全看不出的错误：**8 通道分装的目标体积被写成了
"每列总量"而不是"每通道量"，每孔多加 8 倍试剂**——语法完全合法，账本对终态时才暴露。
这类错误靠人工看 XML 基本不可能发现。

已验证项目的说明书母版版式，最后 UTF-8 打包：

## 过程中踩到的三个真实的坑

1. **循环容器的写法**：builder 的 `loop` 必须用 `as` 接住子容器再往里写活动，
   否则活动全部落进外层、循环体为空——文件能打开，执行是错的。
2. **移板指令的板号格式**：裸数字（`'11'`）而非 `'POS11'`，格式不对模拟直接报
   "源位无板"。
3. **体积语义**：`AspirateVolume / DispenseVolume` 是每通道量。8 通道分装时把
   "每列总量"填进去，就是 8 倍剂量。

三条都已写进账本审计，后续项目会在 S3 阶段自动拦截。
