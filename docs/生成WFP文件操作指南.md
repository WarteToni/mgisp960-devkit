## 〇、首选路径：wfp_builder 直接生成（2026-09-10 起）

**从零生成 WD 工程不再走"spredo 脚本→转换器"两步**，用 `scripts/wfp_builder.py` API 直构：

```python
from wfp_builder import Wfp
w = Wfp("工程名", deck_main=[24位7元组], deck_swap=[同], sw="1.9.0.395")  # 395 硬规则
with w.root().block("阶段名") as b:      # 语义命名生成时即写，无需 post
    with b.loop("col", 4, disp="循环·HB×4列"):
        b.aspirate("POS21", 1, volume=7, z='3.2-0.5*col', tips=8, ...)
w.save("out.wfp")
```

样板 `scripts/wfp_builder_示例.py`（内含自证：重生成参考工程并逐字段比对）（50 液体活动与转换器产物字段零差异验收）。
验收基准：`scripts/参考工程_结构示例.wfp`（结构金标准）+ references/09 §八.3 检查表。

**下文第一~四节的两步路径（spredo→转换器）仅保留给"已有 spredo 脚本转 wfp"的场合。**

## 一、原理：.wfp 是怎么被生成的（兼容路径）

### 1.1 .wfp 格式一句话

`.wfp` 是**未加密的记录流**：每条记录 = `int32 大端长度前缀 + UTF-8 内容`。
头部之后按模块排列（MainDeck → Workflow → 每次换台一个 DESK）：

| 段 | 形式 |
|---|---|
| 头部 | `Release V1` → 工程名 → 配置号`'2'` → 创建/修改时间戳（16B） → **模块计数 int32** |
| Deck 模块 | 类型名记录（121B 程序集全名）→ 模块名（`\MainDeck/`、`DESK 2`）→ `FF×4` 分隔 → 台面 JSON |
| Workflow 模块 | 类型名记录（133B）→ `WorkflowModuleModel` → `FF×4`（即"名为 null"）→ 流程 JSON |

### 1.2 生成器做什么、不做什么

`scripts/spredo转wfp_生成器.py` 的工作分两半：

- **自己做（全部内容）**：AST 解析 spredo 脚本 → 活动树 JSON（Aspirate/Dispense/MvKit/PcrRun/…全部指令）+ 两个台面 JSON（板位/耗材/PosType 编码）→ 按活动 schema 白名单过滤 → 重算长度前缀写出。
- **向模板借（纯骨架，零内容）**：9 条固定记录——`Release V1`、Deck/Workflow 类型名（.NET 程序集全名，恒定值）、模块名记录、头部时间戳。这些字段在新工程里一字不变，模板只是它们的"格式锚点"。

**为什么不能完全不要模板**：生成器写的是 JSON 载荷与计数，而类型名记录必须与目标软件的 .NET 程序集严格一致（多余字段/错版本串会被反序列化器直接拒载），且本机没有"试着加载 .wfp"的模拟器——唯一的验收是现场 WDesigner 打开。模板把这些字节级风险锚死。仓库自带的合成模板让这个前置变成"零准备"（见下）。

## 二、准备模板（三选一）

| 路径 | 适用 | 操作 |
|---|---|---|
| **① 仓库自带（推荐）** | 所有人 | 直接用 `scripts/最小骨架模板.wfp`——程序化合成的单换台最小合法工程，零公司/项目信息，clone 即用 |
| ② 自己的工程 | 手头有 960 项目文件 | 任取一个**单换台**结构的 `.wfp`（用 WDesigner 打开，台面列表 = MainDeck + DESK 2，恰好一次换台）。⚠️ 只有 MainDeck 没有换台台面的工程不可用，生成器会报错 |
| ③ 现场软件非 1.9.0.395 | 版本不匹配时 | 用合成器重生成对应版本模板（见下），生成器加 `--sw <现场版本>` |

**版本说明**：模板与生成器默认对齐软件 `1.9.0.395`（作者现场实机版本，2026-09-10 实锤）。现场软件为 `1.9.0.398` 时：

```bash
# 一步得到 398 版模板（产物可放任意位置）
python3 scripts/最小骨架wfp_合成器.py 我的模板_398.wfp --sw 1.9.0.398
```

（模板骨架里的 `1.8.0.323` 是模块类型库版本，与软件版本无关，恒定不动。）

## 三、脚本的前置限制

生成器按"单换台约定"解析脚本，源脚本需满足（本 skill 生成的工作流 A 脚本天然满足）：

1. **单换台结构**：`def first_feature(): return [...]`（开机台面 7 元组）+ 顶层 `SWAP1_POS = [...]`（换台后台面）；
2. **require2 循环数选择不转换**：PCR 统一替换为固定方法名（命令第 5 参数，默认 `PCR_14C`，在 WDesigner 里可再改）；
3. 不支持的调用会被跳过（`home`/`init`/`binding_map`）并在自检统计里可见——生成后核对活动统计即可发现遗漏。

## 四、生成命令

```bash
python3 scripts/spredo转wfp_生成器.py <脚本.py> <模板.wfp> <输出.wfp> [工程名] [固定PCR方法名] [--sw 1.9.0.395]
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `<脚本.py>` | ✅ | spredo 脚本（见第三节限制） |
| `<模板.wfp>` | ✅ | 第二节三选一 |
| `<输出.wfp>` | ✅ | 输出路径 |
| `[工程名]` | — | 默认取输出文件名；建议与交付项目名一致 |
| `[固定PCR方法名]` | — | require2 替代，默认 `PCR_14C` |
| `--sw` | — | 现场软件版本，默认 `1.9.0.395`；398 现场模板与生成器都要 `--sw 1.9.0.398` |

示例：

```bash
python3 scripts/spredo转wfp_生成器.py My_Library.py scripts/最小骨架模板.wfp out/My_Library.wfp My_Library PCR_14C
```

## 五、生成后必过：产线惯例对齐（post 直改）

生成器直出的 wfp 是"能打开的最小形态"——**不是产线质量**（台面可能缺位、流程平铺、活动全默认名）。规范化基准=现场现役工程（Reference，只读），做法见 `references/09_WD工程_wfp文件生成.md` §八：

```bash
# 改 CONFIG①~⑤（版本串/Block名/试剂映射/Loop上下文/分支名）后：
python3 scripts/wfp后处理_模板.py out/My_Library.wfp out/My_Library_final.wfp
```

产出：阶段 Block 分组 + 全活动语义 DisplayName + Parallel 分支中文名 + 版本串归一（等长替换）。**写出后必 hexdump 头 48B 验证文件头完整**（历史 bug：字符串记录误写 r[1] 把头写成单字符）。

## 六、验证产物（三步，别跳）

1. **生成器自检**：跑完自动重扫输出文件，应看到 `自检: 11 条记录` 与活动统计（各指令条数）。统计里出现预期外的指令名 = 脚本里有未覆盖的调用，先解决再交付；
2. **WDesigner 实机打开**（必须）：台面视图 24 板位齐全、流程视图活动树完整、无红色报错节点；
3. **软件模拟**：WDesigner 模拟通过后控制软件加载，再安排实机水跑。

**已知边界**：`TempSleep` 与 Parallel 内层 Block 的部分字段无原厂实例背书（推断值），若打开时报错，按报错信息对应字段修正即可（方法论见 `references/09` §四）。

## 七、报错速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `模板头部布局异常：'2' 配置号…` | 传进来的不是 WDesigner 保存的 .wfp | 换第二节合规模板 |
| `模板头部布局异常：模块计数/Deck 类型名…` | 模板没有换台台面（纯 MainDeck 工程） | 换单换台工程 |
| WDesigner 打开报反序列化错误（"系统无法读取此项目文件"） | 软件版本与产物程序集串不匹配，或文件含更高版本新增字段 | `--sw` 对齐现场版本（默认 395）；外部传来的文件见 `references/08` 踩坑库"wfp 拒载诊断树" |
| 打开正常但个别节点红 | 推断字段与现场版本差异 | 按 `references/08` 踩坑库对照修正 |

## 八、模板从哪来：最小骨架的合成

`scripts/最小骨架模板.wfp` 不是原厂文件，是 `scripts/最小骨架wfp_合成器.py` 按上述格式**程序化拼装**的产物：

- MainDeck + DESK 2：24 板位按原厂台面规律（POS5 高板位、POS24 垃圾桶位、POS1-4 禁机械臂夹取），KitName 全空；
- Workflow：GlobalSequence + 单个 Initialize 占位活动；
- 内置两道自检：记录流扫描 + 布局级硬解析（零尾余断言），生成即验证。

产物经与真实工程 byte-diff 骨架比对、并以它为模板生成过 444 节点级工程（与原厂模板产物载荷 byte 级一致）。**首次在自己现场使用前，仍请先用它在 WDesigner 打开一次确认**——这一步省不掉，也不应该省。
