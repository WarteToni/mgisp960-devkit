# 踩坑实录（报错调试时先查这里）

> 2026-08 RNA 一步法项目全量实测踩坑。按"报错现象 → 根因 → 修法"组织。
> 新报错先对号入座，90% 有原型。

## 一、模拟/运行报错

### 1. `POS20 currently has kit, and no more kit is allowed`
- **根因**：pos_type_map 声明了该位有板（如 `["Deepwell...","shake"]`），但物理真实是空振荡器；mvkit 放板时软件 loose_check 拒绝
- **修法**：声明改 `[None,"shake"]`（空振荡位，实机验证版 1_DOP.py line11 实机写法）
- **原则**：pos_type_map = 当时物理真实状态，不是"这个位将来是干嘛的"

### 2. `TypeError: 'NoneType' object is not callable`
- **根因**：调用了当前环境不存在/值为 None 的 API
- **误诊留档**：当年曾怀疑 `temp_sleep_a()` 是此错，后源码级核对实锤
  temp_sleep_a/temp_sleep **源码等价**（真因是当时的 POS20 has kit，见 #1；
  结论见 02§四）——习惯用 `temp_sleep()` 即可；`log()` 控制软件环境未验证，慎用
- **排查法**：不确定的 API 查 spredo 源码（02§四）；无存档时与实机验证版
  （1_DOP/2_libraryprep）逐一对照，验证版没有的就是嫌疑

### 3. 台面解析失败（首次加载即报错）
- **根因**：振荡位写纯字符串 `"耗材"`，应为列表 `["耗材","shake"]`
- **修法**：pos_type_map 振荡位一律列表格式

### 4. `SystemError: Operation over 02:00:00`
- **根因**：dialog 弹窗挂 2 小时无人点继续，超时
- **定性**：非 bug。模拟时弹窗要及时点；说明书注明"弹窗 15min 内处理"

### 5. WD → spredo 迁移的 12 处惯犯（2026-08-24 逐条实锤）
`pcr_stop`→`pcr_stop_heating`；漏 `shake.binding(spx96)`；非法标记
（Temp→Temp_Module、Mag(DW)/Magnet→MagRack、删 Higher/LowerPosition）；
update_feature 9 字段+'POS1'（应 7 字段+'Pos1'）；换台 binding_map 3 元组
（应字符串式）；dialog 4 参（应单参）；`initialize()`（应 init(spx96)）；
漏结尾 `home()`；report 位置参数（应关键字）；unload_tips 带 Tips 键（应 Well）；
pos_type_map "temp" 二元（应纯字符串）；temp_sleep_a（应 temp_sleep）

## 二、实机隐患（模拟不报错但实机会炸）

### 6. 弹窗文本与脚本逻辑矛盾
- **案例**：弹窗写"取出 Pos1-8 吸头盒 8 盒"，但 Pos5 八头盒跨全程 12 列不换
  （换台后还有 6 次 load_tips 从 POS5 取）→ 操作员照弹窗丢弃 → 后续无枪头
- **修法**：弹窗三栏清单（取出/保留/放入）必须与 load_tips 台账核对；
  交付前把"弹窗文本 vs 脚本枪头/板位使用"列入验证清单
- **教训**：模拟不校验枪头盒存在性——文本类错误只有人工核对能拦住

### 7. 说明书脚本名/路径过时
说明书里的脚本文件名、拷贝路径必须与交付包实际结构一致（交付包更名后
说明书要重新生成或定点替换）。

## 三、工程类坑

### 8. 报错误诊：截图不可靠
- 弹窗截图读错行号/丢帧曾导致误判（把 POS20 has kit 误诊为 temp_sleep_a 的
  TypeError，白修一轮）
- **纪律**：以软件导出的 Script.log 为准（用户放桌面日志 zip）；行号换算
  `脚本行号 = 日志行号 − 139`（wrapper 偏移，本平台实测值）

### 9. 说明书生成器替换顺序敏感
长句先被部分替换会改写文本，导致后续完整句条目失配——用**唯一前缀定位**
+ 计数断言 + 旧标识清零断言。

### 10. macOS zip 中文乱码
Info-ZIP `zip` 不设 UTF-8 flag，Windows 解压中文文件名乱码——**用 Python
zipfile 打包**并校验 `flag_bits & 0x800`（纯 ASCII 文件名不需要 flag，正常）。

### 11. 英文版翻译的词序污染
字符串映射替换必须**长串优先**（"二链合成"先替换会把"4/4 进行二链合成反应"
啃成混合体）——映射表按 key 长度降序执行。

### 12. 版本与命名纪律
- 定稿脚本更名/术语规范变更后：git mv（保历史）→ 全项目 grep 旧名清零 →
  交付包重打 → 记忆同步，四件事一次做完
- 命名规范（用户 2026-08-29 定）：**"Python 直写版"**（无需图形界面）vs
  **"WD 版"**（WDesigner 图形界面）——不要再用指向任何厂商发行版的语法名做标签

### 13. ast.walk 是广度优先——参数提取必须源码序
用 ast 提取操作序列做 diff/对齐时，ast.walk 的顺序是 BFS，配对全错。
必须用 iter_child_nodes 递归的源码序遍历。（V2.3 对齐时踩过）

### 14. wfp 是源头，.python 是导出产物——读流程只认 wfp
项目目录同含两者时一律读 .wfp（保存即最新）；.python 是机器里从 wfp
导出更新的产物，天然滞后。用户在 WDesigner 改参后只存 .wfp 不导出 .py
时最典型——对齐必须解析 wfp 活动 JSON，.py 是旧的。配对用"分段+单调
指针+签名"，未配对项先核对是否为设计差异（删步骤/废液分流等）再下结论。

### 15. 参数对齐必须含结构层（V2.4 对齐教训）
对齐新版基线时不能只覆盖参数值：循环壳增删（V2.4 删了
`for z in range(int(1))`）、操作的增删都要同步。对齐后必须做
**逐操作终核**（op/板位/体积/Z 全字段，容忍 str/float 与寻址格式差异），
不能只信对齐器的配对结果——Well 寻址 vs Col 寻址不归一会导致静默漏配。

### 16. WDesigner 改流程后控制软件不生效 / 异常关闭丢工程（HelperDoc S10 p68/69）
- **改流程保存后必须刷新**：控制软件运行向导 >【应用方案】下拉列表 > 刷新，
  重新加载流程，否则无法生效——与 #14（.python 导出滞后）叠加：
  WD 改完 = 保存 .wfp + 刷新控制软件 +（需要 py 时）重新导出，**三件事一次做完**
- **异常关闭抢救**：WDesigner 异常关闭且未及时保存项目 → 缓存文件在
  `C:\MGISP-960\WDesigner\Cache`
- 保存时提示"应用方案存在错误" → 找标红文本框按提示修改，否则项目无法同步控制软件

## 17. 换盒/换台后 pos_type_map 漏更新"滞留板"（2026-09）
现象：静态自检 A 项报"mvkit 源位无板"，但流程逻辑明明 mvkit 过去了。根因：快速换盒
（纯枪头、不动板）后重写 pos_type_map，把**物理上仍停在该位的板**（如磁架上晾干的
纯化板）写成了 None——声明≠物理真实（红线 1 的镜像面）。修法：每次重写台面前先过
一遍"哪些板没被取出"，滞留板照实声明；全面自检 D 项互证可机检。

## 18. 多事件共用储液板的装载漏加（2026-09）
现象：TE/乙醇等"每孔储液、全程多次取用"的板中途吸空。根因：装载表只按第一次事件
用量设计，漏加后续事件（如 TE 板 = 稀释 9 + 洗脱 42 + 23 + 32 = 106+死体积，只按首
事件装载）。修法：装载量 = Σ全部事件 + 死体积，账本终态断言兜底（"储液板未吸空"）。

## 19. 生成器头部偏移硬编码绑定"模板工程名长度=35B"（2026-09-10 已修复）
现象：`spredo转wfp_生成器.py` 旧版用 `tpl[53:74]` 硬编码切头部（'2'+DateTime×2），
与模板工程名**字节长度**强耦合（例：某 35 字符工程名时切点才正确）；
换任何其他名长的模板，产物头部整体错位（配置号/时间戳/计数区被模板中段字节填充）。
更隐蔽的是**生成器自检发现不了**：内置记录流扫描器靠"可打印比例>92%"启发式咬合，
错位产物会咬出一条 768B 的假记录（内容 `\x00yDeck...`）却照样"自检通过"——
444 节点历史产物（前身脚本所出）就带着错位头与缺失的 FF 填充，自称"解析自检通过"。
教训两条：① 二进制格式解析禁用固定偏移，按布局逐记录推进+断言；
② 自检器不能用与生成器同源的启发式扫描器自己验证自己——要**布局级硬解析**
（逐段类型断言+零尾余），`最小骨架wfp_合成器.py` 的双自检是现成范例。

## 20. wfp"打开项目文件失败/系统无法读取此项目文件"诊断树（2026-09-10 三案例完整复盘）
**纪律：先抓日志再分析内容**——WDesigner 日志在 `C:\MGISP-960\WDesigner\Logs\Logs_日期.txt`
（log4net，含完整异常堆栈），弹窗只有一句通用报错，堆栈才指认真因。当天三个案例
同一弹窗、三种根因，全靠日志区分：

**根因①（最常见）UnauthorizedAccessException = 权限问题，文件根本没被读到**：
微信传输的文件落 Mac 是 **444 只读**（`-r--r--r--@`），经 Parallels 共享映射成
Windows 只读文件，而 WDesigner 打开工程要求**写权限**（打开后要能保存）→
`FileStream` 直接被拒。案例：Oligo产物文库构建.wfp、纯化.wfp（他人微信传来）。
**任何内容层诊断（版本/字段/布局）在权限问题未排除前都是空谈**——当天对 Oligo
的"排空增强字段拒载"分析即误诊，权限修复（`chmod 644`）后**原件带未知字段直接
打开成功**（活动树 `RootObject:JObject` 动态解析，字段层宽松，"多余字段即拒"
被证伪）。修复：Mac 端 `chmod 644`；复现验证用 `[IO.File]::Open($p,'Open','ReadWrite','Read')`
（ReadWrite 被拒=权限问题，只读能开=内容问题）。schema 白名单仍保留为生成器
防御性过滤，但不再作为拒载诊断依据。

**根因② JsonReaderException "Unexpected character X" = 布局/内容切分错位**：
`DeckModuleModel.Import(str)` 收到非 JSON 开头的字符串（"W"= Workflow 类型名串），
即记录流切分点与加载器期望不符。合成器骨架产物布局与原生文件**不同构**（记录数
3 vs 2、Deck→Workflow 之间原生有类型名等记录而骨架缺失）——骨架"发别人打不开"
的真实根因候选，版本串匹配与否反而未及验证。**修复中**（2026-09-10 记）。

**根因③ 版本串不匹配（理论线，本日未实锤）**：.NET 程序集限定名精确匹配，398
产物在 395 实机理论上拒载；但当日"398 骨架打不开"现象与根因②混在一起，单一归
因为版本串**证据不足**。版本对齐仍是铁律（生成器默认 395=现场实机）。

**诊断顺序**：① `stat` 查 444 权限（微信文件必中）→ ② 日志堆栈定类别
（Unauthorized=权限 / JsonReader=布局 / 类型绑定=版本）→ ③ 权限修复后
`ReadWrite` 探针复验 → ④ 内容层分析只在日志指向内容时才做。
工具链：Mac 端 `ffffffff`+4B 大端长度切块解析（嵌套子对象用 raw_decode+
surrogateescape 防误报）；`prlctl exec` 进 VM 反射实机 DLL 查类型是否存在
（Condition2/Require 家族 395 均原生支持，schema 未收录≠软件不认识）。

## 21. "项目文件版本高，升级系统"——版本串必须实证，398≠现场（2026-09-10）

生成器显式传 `--sw 1.9.0.398`（S0 未实证、凭旧档案拍板），产物在 1.9.0.395 现场
软件全部报"项目文件版本高，升级系统"。而 skill 生成器/合成器**默认本来就是
395**（作者实机一致）——是显式传参覆盖了正确默认。
**纪律**：① S0-⑧ 版本必问且必实证：拿一个现场现役 .wfp 看 ActivityType 的
`Version=` 串，不凭档案；② 不确定时不传 --sw（用默认）；③ 已产出的文件可
**等长字节替换**补救（'1.9.0.398'/'1.9.0.395' 同长度，长度前缀不动），
替换后必须完整 parse 验证。参考：09 §八。

## 22. post/直改写出把字符串记录写成 r[1]（字符索引）——文件头变单字符（2026-09-10）

直改工具 write_records 的 else 分支 `wr(r[1])`：对字符串记录 'Release V1'
取的是**字符索引** r[1]='e'——文件头两条记录变成 `00 00 00 01 'e'` / `'r'`，
WDesigner 报打不开。危险点：**液体活动区可能完全正常**（错位不一定立即暴露），
"账本能跑"不等于文件没坏。
**纪律**：直改/后处理工具写出后必做两道断言：① hexdump 前 48B 看头两条记录；
② 完整 parse 且 release=='Release V1'、尾余=0。修复写法见 wfp后处理_模板.py。

## 23. spredo转wfp 生成器三坑（2026-09-10 集中踩实）

1. **`for x in range(0, 4)` 双参 range** → 生成器取 args[0]=0 当 LoopCount →
   **Loop 0 圈，所有循环体在 wfp 里被跳过**（实机跑会静默漏掉全部循环段）。
   必须 `range(4)` 单参数（变量从 0 起）。
2. **裸循环变量 `Col: col`** → 生成器 const() 对非表达式 Name 返回 None →
   活动字段 Col='None'。必须写表达式形态 `col + 1`（原厂公式存法）。
3. **行尾注释**：`...})   # 注释` 使生成器语句块 endswith('})') 判定失败，
   块未闭合，下一条调用触发缓冲重置 → **语句静默丢失**（一次丢了 7 处）。
   参数行尾不放注释，或注释独立成行。
信号：生成后必对活动统计（生成器自检输出）与脚本调用清单**逐项对数**；
账本活动数骤减/终态突变都是信号。见 09 §八。

## 24. 8 头操作漏 'Tips': 8 —— 默认按 96 头全板执行（2026-09-10）

spredo 脚本 8 头段（POS5 取头后）的 aspirate/dispense/empty/mix **每个 dict
都必须带 'Tips': 8**；漏写按默认 96 = 全板语义执行（账本 sub(ALL) 全板扣减、
实机 8 头任务变 96 通道动作）。信号：账本终态负值满屏/储液井被多列同时扣减。
另一面：96 头只有全板/单列两模式，部分板样本的小体积分装必须 8 头——
通道分工设计见 09 §八.2。
