# 代码审查 · 说明书对照法（功能 4）

> 输入：一份中文手动说明书（docx/pdf）+ 一段代码（spredo .py / WD 导出 .py）
> 或一个原始 .wfp 工程文件。
> 输出：**审查报告**——分级问题清单 + 存疑清单。
> 默认只审不改；用户要求修时才动手，修完按 07 四层自检复验。

## 〇、到场三问（先定审查范围）

1. **审查对象与范围**：只审化学正确性，还是含硬件符合性/参数基准/液体处理质量
   （液面/残留/回收）？（默认全七维）
2. **有没有基线版本**（如已验证的旧版脚本）→ 有则加做 07 第 3 层参数 diff
3. **.wfp 是否伴随同源导出的 .py** → 两者并存时先做互相对齐核验
   （WD 改参未导出时 **.wfp 是唯一权威源**，踩坑 #14），再定审查基准

## 一、说明书 → 审查基准（按 00 的方法）

把说明书抽成三张**基准事实表**（这是审查的标尺，不是生成用的完整理解表）：

1. **试剂分类表**：组分 → 角色（酶/结合/洗涤/洗脱/磁珠/接头/样本）→ 约束（冰上/避光/怕盐/加入顺序）
2. **操作序列表**：每步五元组 `[输入] + [试剂及体积] + [操作] + [温控/等待] + [输出去向]`
3. **温控表**：温度×时间×循环数（对照 04 的换算规则：min→s、循环 LoopNumber=N-1）

落不成五元组的步骤 = 审查基准缺口，先问用户补齐，不要带着模糊往下审。

## 二、代码 → 统一操作序列（按形态选提取法）

| 输入形态 | 提取方法 |
|---|---|
| spredo .py | AST 提取 API 调用序列——**必须源码序遍历**（iter_child_nodes 递归；`ast.walk` 是 BFS 会配对错乱，踩坑 #13） |
| WD 导出 .py | 同上，注意 `a_` 前缀 / `initialize()` / 9 字段台面等 WD 语法特征（03） |
| 原始 .wfp | 按 09 解析记录流 → 活动树 JSON → **DFS 拍平**（与 py 执行顺序逐行对位）→ 活动短名经 02§六对照表映射成统一操作语义 |

统一序列格式：`[序号, 操作原语, 板位, 体积/速率/Z高, 温控, 弹窗/换台标记]`，
供第三步与基准事实表逐步对位。

## 三、七维逐项核对

| 维度 | 核对内容 | 依据 |
|---|---|---|
| **A 化学一致性**（核心） | 每步试剂/体积/加入顺序对照加样表；温控（温度×时间×循环）对照温控表；磁珠比例方向；孵育时长；注意事项落地（冰上=温控位、避光、轻柔混匀=低速率、勿涡旋=改 mix）；**手册给多档循环数而代码写死单档 → 列存疑项**（是否应做弹窗选择模块，见 00 §四问题7） | 说明书 + 00 |
| **B 硬件符合性** | pos_type_map=物理真实状态；POS1-8 枪头位不放板；仅 POS5 八头取枪头；mvkit 源有板/目标空；废液 <1300μL/孔；并发模型（臂×1、PCR×1，并行唯一合法形态=PCR等待×手臂预备） | 01 + 05四/五 |
| **C 语法/API** | 7 字段台面 + 4 种合法标记；API 是否真实存在（NoneType 陷阱）；dialog 单参；换台后 update_feature+binding_map 成对；首尾 home()；WD→spredo 迁移 12 处惯犯 | 02 + 08#1-5 |
| **D 参数基准** | 液体参数（速率/空气垫/Z高/混匀）对照已验证基线；无出处的自创参数标"待水跑验证" | 05二 + 07第3层 |
| **E 文本一致性** | 弹窗三栏清单（取出/保留/放入）↔ 枪头/板位台账 ↔ 说明书换台页三者互证；脚本名/拷贝路径与实际结构一致 | 08#6/#7 |
| **F wfp 专项**（仅 .wfp 输入） | 活动字段过一遍 `scripts/wfp活动schema.json` 白名单；UpdateDeck ↔ update_feature+binding_map 映射完整性；PosType/Available 编码陷阱（空 PCR 位 Available=false，有板 PCR 位=true，置错→台面灰、引用全红） | 09 + 生成器注释 |
| **G 液体处理质量与回收** | 吸得足？吸得净（残留/乙醇吸干净）？打得净？产物回收最大化（洗脱多吸）？速率/气垫匹配？**有无违反 13 铁律（回收无安全余量/磁珠混匀降档；负 Z 官方允许，
磁珠位确认降速或已标定即可）**——定量核算见下 | 11 + **13** + 05 |

### G 维细则：液体处理质量与回收核对（用 11 定量）

| 检查项 | 核对方法 | 典型问题 |
|---|---|---|
| **G1 吸得足** | 每次吸液：吸前液面高（11 曲线）vs Z——全程枪头在液面下？大容量单次吸时液面在吸的过程中下降（降幅≈体积/截面积），Z 是否够深；速率/空气垫/吸后延时对照 11 §二分档表 | Z 高于液面→吸空；速率过快→吸不足/气泡；气垫不足→液体进枪头轴 |
| **G2 吸得净（残留）** | 同孔多次吸液是否有 Z 递减（循环公式）；末次吸取 Z 是否足够贴底（推荐极低正 Z 0.1–0.3；负 Z 官方允许但须标定）；**定量：Z 下限反查曲线→折算残留体积**；乙醇洗涤两轮是否都尽量吸净 | 后段吸液吸空；乙醇残留抑制下游反应 |
| **G3 打得净** | empty Z 对照 13 §七.4 液面锚：= 打完后液面 − 0.4（带宽 −0.25~−1.0），残液零挂壁；无液面跟踪时回落 11 §二体积档表（权衡"低→气泡、高→排液不完全"）；黏稠试剂低速排空；**悬空打液（乙醇）：查是否悬空+靠壁排净、打/去枪头分离（13 §七.4c、12 §二）**；批量核算用账本模板（13 §十） | 气泡；排液不完全→实际加样量偏低（挂壁损失 0.5~2µL）；**打乙醇浸没/打去同枪头→交叉（P2）** |
| **G4 产物回收最大化** | 终洗脱：**最大可吸量 = 洗脱体积 − Z 下限以下液体（曲线反查）− 安全余量**；脚本固定吸取量 < 最大可吸量 → 建议加大吸取量或二次回收；吸液 Z vs 磁珠层厚度（大体积磁吸后珠层更厚 → Z 应更高） | 产物留在孔里；吸到磁珠层→污染 |
| **G5 挥发与时序** | 乙醇板/敞口板按开放时间算液面下降→余量是否够；干燥窗口是否过久 | 挥发液降→后段吸不足 |
| **G6 速率匹配** | 吸/打液速率按 11 §二体积档+试剂类型（普通/黏稠）核对；磁珠预混匀必须 200-250 高速+15-25 次（不许降档）；跨样本转板防飞溅 | 磁珠重悬不足→回收率整体偏低 |

**定量报告要求**：G 维问题必须给估算值（残留 ~X μL / 可多回收 ~Y μL），
用 11 曲线反查折算，不空谈。**分级**：定量回收损失/吸液不足 = **P1**；
残留风险未定量 = **P2**；"可以吸更多/更贴底"类优化 = **P3**。

## 四、问题分级与报告格式

**分级**：
- **P0 实机必炸/撞机**：硬件红线、不存在的 API、废液超容、板流冲突
- **P1 化学错误**：体积/温度/时长/试剂顺序与说明书不符
- **P2 带险差异**：自创参数、弹窗与逻辑矛盾、双源不一致（.py vs .wfp）
- **P3 建议**：时间线可优化、冗余步骤、命名不规范

**报告每条 = 定位（脚本行号 / wfp 活动节点）+ 对照出处（说明书章节）
+ 判定依据 + 修复建议**。
确认问题与存疑分开列：**存疑项列清单让用户拍板，不单方面下结论**
（如平台惯例热盖 110℃ 与手册 105℃ 的差异——披露，不擅改）。

  （枪头量程/排液≤吸液/公式 Z）+ 语法红线 + 弹窗互证等 11 类检查一次完成

- `references/13`：建库模块参数规律 = **G 维的判定规则**（铁律 + 逐模块约定 + 审查定性表）
- 07 四层自检全部适用（第 4 层软件模拟由用户执行，报错取证要 Script.log）
- 08 踩坑实录：报错/隐患对号入座，90% 有原型
